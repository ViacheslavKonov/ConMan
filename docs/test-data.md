# Тестовый датасет ConMan

Датасет находится в `backend/app/data/demo-v1.json` и входит в backend-образ.
Загрузка доступна через CLI; web-интерфейс и HTTP API не меняются.
Все имена и организации вымышлены. Адреса используют зарезервированный
домен `example.com`. Финансовые операции являются записями в тестовой базе,
никакие деньги не перечисляются. Учётные записи и пароли не создаются.

## Состав

| --- | ---: |
| Мероприятия | 2 |

| Записи истории check-in и выдачи бейджей | 13 |

Основное мероприятие — `[ДЕМО] Конвент «Город мастеров»` (`DEMO-EVT-01`),
10–12 октября 2026 года. Открыты регистрация, пожелания и check-in.
Второе — архивная ярмарка 23–24 мая 2026 года (`DEMO-EVT-02`).
Даты фиксированы, чтобы состав набора оставался воспроизводимым.

В наборе есть полный стол и половины A/B, свободные столы, все семь статусов
бронирований, отсутствие оплаты, частичная и полная оплата, переплата,
полный возврат и отменённый платёж. Тарифы включают разное число помощников;
дополнительные участники увеличивают стоимость через штатный расчёт.
Для check-in подготовлены полностью и частично прибывшие команды,
выданные и невыданные бейджи, а также история операций.
Пожелания содержат черновик, отправленные формы и отношения «рядом»/«избегать».
Версии планов можно создать обычной кнопкой генерации в разделе планирования.

## Docker Compose

Сначала запустите актуальные образы приложения: миграции выполняются при старте
backend. Для локальной сборки:

```bash
docker compose -f compose.dev.yaml up -d --build
```

Проверьте датасет и возможные конфликты, не добавляя записи:

```bash
docker compose -f compose.dev.yaml exec -T backend python -m app.cli load-demo --dry-run
```

Загрузите данные:

```bash
docker compose -f compose.dev.yaml exec -T backend python -m app.cli load-demo --yes
```

Чтобы при первой загрузке выбрать демо-мероприятие текущим:

```bash
docker compose -f compose.dev.yaml exec -T backend python -m app.cli load-demo --yes --make-current
```

Для production Compose используйте `-f compose.yaml`; для Portainer Compose
на сервере — `-f compose.portainer.yaml` с окружением вашего стека.
Команда работает в контейнере `backend` и использует уже настроенные `DB_*`.

## Portainer

1. Используйте backend-образ версии, в которую включён этот загрузчик.
2. Откройте **Containers → backend-контейнер вашего стека → Console**.
3. Подключитесь через `/bin/sh`.
4. Выполните проверку:

   ```sh
   python -m app.cli load-demo --dry-run
   ```

5. Выполните загрузку:

   ```sh
   python -m app.cli load-demo --yes --make-current
   ```

Если администратор ещё не создан, создайте его штатным экраном первого запуска.
Загрузка датасета не закрывает этот экран и не создаёт обходной доступ.
После загрузки обновите страницу приложения. Если `--make-current` не использован,
выберите `DEMO-EVT-01` в разделе мероприятий.

## Результат и повторный запуск

Команда печатает JSON с описанием набора, количеством записей, UUID и кодами
мероприятий, временем импорта и признаком изменения текущего мероприятия.
Поле `records` описывает состав поставляемого набора; после ручных изменений
демо-записей оно не является подсчётом текущего содержимого базы.

- `ready` — проверка `--dry-run` прошла, данные ещё не загружены.
- `loaded` — набор загружен одной транзакцией.
- `already_loaded` — набор ранее загружен; повторный запуск ничего не меняет.

Коды возврата: `0` — успех, `1` — ошибка проверки или базы, `2` — отсутствует
подтверждение `--yes` при запуске без `--dry-run`.

Загрузчик проверяет ссылки, уникальность кодов, даты тарифов, владельцев заявок,
допустимость пожеланий и пересечения мест за столами. Если в базе уже существует
запись с кодом или UUID из набора, импорт прекращается. Существующие записи
не используются как демо-данные и не перезаписываются.
Два одновременных запуска сериализуются блокировкой PostgreSQL и создают один набор.
При ошибке все добавленные записи и отметка импорта откатываются. Значения обычных
PostgreSQL-последовательностей могут иметь пропуски после отката.

Завершённый импорт отмечается в `app_settings`, включая контрольную сумму набора,
и фиксируется в журнале аудита с источником `CLI`. После импорта записи можно
редактировать штатными экранами. Повторная команда сохраняет эти изменения и
не восстанавливает удалённые записи. Даже `--make-current` при повторном запуске
не переключает мероприятие: используйте обычный выбор в web-интерфейсе.

Для нового чистого прогона используйте отдельный тестовый стек с отдельным томом
PostgreSQL. Загрузчик не очищает базу и не сбрасывает существующую установку.

## Проверка реализации

```sh
cd backend
pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Тесты используют отдельные схемы PostgreSQL и проверяют состав, финансовые итоги,
рассадку, check-in, совместимость с существующими экранами и отчётами, предварительную
проверку, конфликты, откат, повторную и одновременную загрузку.

Проверено на Python 3.13 и PostgreSQL 17: девять тестов загрузчика и шесть
существующих тестов первого администратора прошли. Отдельно проверен backend
Docker-образ без монтирования исходников: старт с реальными миграциями,
`--dry-run`, загрузка, повторный запуск и доступность первоначальной настройки
администратора. Временная база и контейнер после проверки удалены.
